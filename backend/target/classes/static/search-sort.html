THEORY & BENCHMARKS

Conceptual Performance Comparison

Asymptotic computational time complexities and suitability criteria for Phase 3 algorithms

Algorithm Category Best Case Average Case Worst Case Space Complexity Prerequisite & Operational Characteristics
Linear Search Sequential Scan O(1) O(n) O(n) O(1) No pre-sorting needed. Evaluates elements one-by-one sequentially until match is found or end of list is reached.
Binary Search Divide & Conquer O(1) O(log n) O(log n) O(1) Requires strictly sorted input. Repeatedly divides the search range in half by comparing query against median element.
Insertion Sort Incremental Placement O(n) O(n²) O(n²) O(1) In-place, stable sort. Highly efficient for small or nearly-sorted datasets; high shift overhead for large reverse-ordered arrays.
Quick Sort Partition Divide & Conquer O(n log n) O(n log n) O(n²) O(log n) Selects pivot, partitions array into smaller and larger elements, and sorts recursively. Highly efficient general-purpose sorter.
MCA Academic Note on Big-O Notation: The time complexities displayed above are conceptual asymptotic upper bounds that measure how computational comparisons scale as the input size $n$ grows toward infinity ($O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2)$). They do not represent fixed wall-clock execution times, which vary depending on CPU caching, memory allocation, and operating system load.
